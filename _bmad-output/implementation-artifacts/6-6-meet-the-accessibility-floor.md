## Story

I want reduced-motion, screen-reader, contrast, and tap-target support,
so that the game is playable and the dread still reads safely.

## Acceptance Criteria

The 6th and LAST Epic-6 story (Visual Identity, Navigation & Onboarding Shell). It SETTLES the standing 4.7 deferral ("the reduced-motion / photosensitivity SETTING + its persistence is Epic 6" + "wiring that setting into `MaterializationView`") and the 6.2 deferral that assigned "the broader accessibility floor (reduced-motion, TalkBack, contrast, ≥48dp tap targets) is 6.6" to this story. It CONSUMES (does not rebuild) the 4.7 `MaterializationPresenter` reduced-motion input, the 6.1 `PumpkinPatchTokens` (text/muted/SLAY-red), the 6.2 `ChunkyButtonStyle` SLAY-icon-and-label enforcement + `CreditPillStyle`/`CodexSlotStyle`, the 6.5 `VeilVoice.Safety` plain-copy firewall, and the existing `ICreditService.OnCreditsChanged` / `CodexService.OnMonsterDiscovered`+`OnCodexCompleted` events.

**AC-1 — Reduced-motion / photosensitivity setting tames motion (the SETTING + persistence + the wider taming)**
**Given** the reduced-motion / photosensitivity setting
**When** it is ON
**Then** the T5 Breach glitch + camera-corruption, the per-tier ambiance INTENSITY, and screen-shake are tamed — **no flashing**; the glitch is **replaced by a static branded transition**; **the dread still reads without strobe/shake**.
- The reduced-motion **SETTING** is a player-controllable, **PERSISTED** value (settles the 4.7 defer: "the SETTING + its persistence is Epic 6"). It lives in `SaveModel` as an additive `bool` (the `StartingCreditsGranted` additive-scalar precedent — NO schema bump, an old save deserializes the absent property to `false` = motion-on, the safe non-tamed default for an existing player who never opted in). A read/write seam (`IAccessibilitySettings` or equivalent) exposes it; the deferred `MaterializationView._reducedMotion` stub is re-pointed at that live value (settles "wiring that setting into `MaterializationView`").
- 4.7 already proved the glitch-OFF taming (`MaterializationPresenter.PlanFor(tier, reducedMotion:true)` ⇒ `BrandedGlitch == false` for EVERY tier). 6.6 ADDS the two pieces 4.7 did NOT tame: **the per-tier ambiance INTENSITY** (today a reduced-motion Nightmare still returns `AmbianceIntensity.Nightmarish`) and **screen-shake**. The taming must PRESERVE the entrance variant + the felt dread (the variant is still its tier's variant; the ambiance still reads "toward the tier" — just not at strobe/shake amplitude). AC-3 of 4.7's discipline ("the dread still reads") is the invariant.

**AC-2 — Dread/danger never carried by a single channel (SLAY-red + materialization audio)**
**Given** non-visual / non-auditory players
**When** dread and danger are conveyed
**Then** **SLAY-red is never the sole signifier** (always + icon + label), and **materialization audio stings always have a visual/caption cue** (audio is never the sole carrier of dread).
- The SLAY half is ALREADY enforced at the descriptor level (6.2 `ChunkyButtonStyle.For(Slay)` ⇒ `RequiresIcon == true` + the fixed `"SLAY"` label). 6.6 PINS this as the UX-DR17 accessibility guarantee (a regression guard — the mutation-testable "SLAY-red carries icon AND label, never red alone") and DOCUMENTS that the render must bind both. 6.6 adds NO new SLAY logic; it pins the existing invariant from the accessibility angle.
- The audio half: materialization carries audio stings (the Breach roar etc.) — 6.6 adds the **decision** that every audio sting has a paired **visual/caption cue** so a non-auditory player still perceives the dread. Modeled on the `MaterializationPlan` (the 4.7 plan) as a derived flag/cue, OR as a small accessibility descriptor that maps a materialization to its required caption cue. The actual audio + caption RENDER stays deferred (the standing Epic-6 view defer); 6.6 supplies the DECISION (a sting ALWAYS implies a visual/caption cue — never audio-only).

**AC-3 — Tap targets ≥ 48dp, contrast holds, muted text never for safety, dynamic type does not truncate**
**Given** Android accessibility
**When** the UI is used
**Then** **tap targets are ≥ 48dp**, **text holds contrast** on the dark surfaces (**muted text NEVER used for safety copy**), **dynamic type does not truncate chunky controls**.
- **Tap target ≥ 48dp:** add the `48` dp minimum-tap-target as a NAMED design token (`PumpkinPatchTokens.MinTapTargetDp = 48` — the dp-scale-lives-in-tokens precedent, UX-DR18). Every interactive component descriptor (chunky button, credit pill, Codex slot, pack card) declares it meets the floor; pin that the floor token is 48 and is exposed for the render to enforce. The actual UGUI min-size enforcement is the render layer; 6.6 supplies the TOKEN + the per-component declaration.
- **Muted text never for safety (the contrast firewall):** `PumpkinPatchTokens.TextMuted` already documents "NEVER used for safety copy (UX-DR17)." 6.6 makes this STRUCTURAL + mutation-testable: a safety treatment's text color is `TextPrimary` (high-contrast), NEVER `TextMuted`. Tie it to the 6.5 `StateTreatment.IsSafetyException == true` firewall — a safety treatment carries (or implies) the high-contrast text role, never the muted one. Pin: safety copy's color role ∈ {TextPrimary}, ∉ {TextMuted}.
- **Contrast holds / dynamic type:** a small, deterministic contrast helper (WCAG-style relative-luminance ratio over `Color32`) proves the body/safety text colors clear a documented threshold against the dark `Surface`/`Background` (a falsifiable, headless pin — NOT a render concern). Dynamic-type-no-truncation is a render/layout guarantee (deferred to asset-authoring) — 6.6 records the requirement + pins the chunky-control labels are not length-bounded in the descriptor (no silent fixed-width clip in the logic layer).

**AC-4 — TalkBack: role + state on every interactive element; credit pill announces balance; Codex count announces on tick-up**
**Given** Android accessibility
**When** the UI is used
**Then** with TalkBack, **every interactive element is labeled with role + state**, **the credit pill announces balance changes**, and **the Codex count announces on tick-up**.
- ZERO accessibility-label infrastructure exists today (the recon confirmed). 6.6 ADDS a pure-logic **accessibility-label model**: a small `AccessibilityRole` enum (Button / Tab / Image / Header / etc. — the closed set the surfaces need) + an `AccessibilityLabel` readonly-struct (role + a human label + an optional state string) + a formatter that produces the canonical TalkBack string ("Slay, button" / "Antlered Shade, 12 of 67, button"). Every interactive component descriptor surfaces its `AccessibilityLabel` (the chunky button, the credit pill, the Codex slot, the pack card).
- **Credit-pill balance announce:** a pure-logic decision that maps a balance CHANGE (the `ICreditService.OnCreditsChanged(int newBalance)` event payload) to an announcement string ("20 credits"). 6.6 supplies the announce-COPY decision (value-in → announcement-string-out); the live subscription + the platform `AnnounceForAccessibility` call is the deferred render/view wiring (symmetric subscribe/unsubscribe — [[failure-path-cleanup-parity]] — owned by the deferred view, NOT the pure presenter).
- **Codex count announce on tick-up:** a pure-logic decision that maps a discovery tick (old count → new count, e.g. via the `OnMonsterDiscovered` signal + `DiscoveredCount`/`UniverseCount`) to an announcement string ("12 of 67 discovered"). Same posture: 6.6 supplies the announce-string decision; the live event subscription + the platform announce is deferred view wiring.
