## 2. What went well

**A. The altitude-split discipline held six-for-six — and was load-bearing for tier placement.**
Not cosmetic: in 6.3, because `Veilwalkers.UI` references `Veilwalkers.App`, the dependency direction *forced* `AppStateMachine` + flow/entry/overlay enums down into App, while descriptor-composing Home/ArHud presenters stayed in UI. 6.4/6.5/6.6 placed logic in UI for the inverse reason. The graph dictated the code location.

**B. Structural-by-construction invariants replaced convention everywhere — the epic's best idea.**
Where an AC was encoded as a *shape*, the violation became unreachable and the test became a one-liner:
- 6.2 `ChunkyStyle.Elevated(...)` → hard-shadow/no-blur (AC-2) true by construction; SLAY-red-never-alone baked into the descriptor.
- 6.5 `SafetyWarning(...)` is the **only** factory setting `IsSafetyException`, sourcing copy only from `VeilVoice.Safety` → a diegetic line on a safety message is unreachable; the no-percentage invariant is structural (`StateTreatment` has no numeric member, pinned by reflection).
- 6.6 `HasAudioSting ⇒ RequiresCaptionCue` pair → a sting with no caption is unreachable even for `default(MaterializationPlan)`.

**C. Two stories hit the headless gate first-run clean.**
6.2 (517/517) and 6.3 (561/561 pre-CR) — the two built directly on the most heavily-CR'd primitives (6.1 tokens, `ChunkyStyle`). Front-loading correctness onto primitives let siblings inherit it (validates the Epic-4 "invest CR on the primitive" bar).

**D. Token single-sourcing made the component layer tamper-evident.**
Hex-as-source-of-truth (6.1) made `descriptor.Fill == PumpkinPatchTokens.SecondaryAccent` non-tautological *because the descriptor truly sources the token*; a hard-coded hex becomes an AC-violating test failure. The pattern recurred and was reinforced (6.4 derived `PremiseCardCount`, 6.5 re-pointed placeholders at `VeilVoice`, 6.6 re-pointed `MaterializationView._reducedMotion` at the live setting).

**E. Adversarial 3-layer CR caught 3 AC violations that shipped green.**
The suite was green while all three existed (detailed in §4). This is the CR's real product.

**F. Intra-epic debt routing worked — IOUs landed on named in-epic owners and were genuinely closed.**
6.1's `Spacing` mutability nit → closed in 6.2 (`int[]→IReadOnlyList<int>`). 4.7's reduced-motion setting+persistence IOU → closed in 6.6 (plus the two pieces 4.7 never tamed). 6.2's "broader a11y floor is 6.6" → closed in 6.6.

## 3. What was hard / recurring struggles (themes in 2+ stories)

**A. Compile-fix on first dev run — the epic's signature friction (4 of 6 stories).** Two sub-classes:
- *Missing namespace import* — 6.1 (`using Veilwalkers.Core` for `GameLog`, CS0103), 6.4 (`SpendResult`/`Result`, CS0246).
- *Internal-not-visible-to `UI.Tests`* (structural) — 6.5 (`StateTreatment.None()`, CS0117), 6.6 (`Hex.Packed`, CS0122; plus a CR-re-gate `FakeStore` missing `DeleteAsync`, CS0535). `Veilwalkers.UI.Tests` has no `InternalsVisibleTo`, so any test reaching an `internal` helper fails. All four caught by the gate's exit-1 first run — but nothing prevents it pre-run. **→ Action Item #1.**

**B. Graceful-degradation / never-throw / null-safety gaps — the most consistent CR class (5 of 6 stories).** 6.2 (`DimTeal` magnitude-dependent → per-channel `Dim()`), 6.4 (unguarded `CompleteOnboarding()`/disclosure-gate violated the "never throws" contract), 6.5 (`PlacementResult.Message` null → blank card), 6.6 (`SafetyTextColor` ignored its parameter; 0/0 degenerate announce). Lesson: a class documented "never throws" must guard *every* external call site; a "clamp/strictly-dimmer" transform must hold per-channel/symmetrically.

**C. Single-source-of-truth desync — two sources for one fact diverge.** 6.4's premise-count AC violation (presenter `PremiseBeats.Count` vs. flow `const 3`) is the headline; 6.1's self-defeating `Assert.AreEqual(5, packed.Count)` is the same class. Fix: pin the *relationship*, not the literal. **→ Action Item #3.**

**D. Invariant claimed in a doc-comment but not enforced in the type (2+ stories).** 6.1 (`readonly int[] Spacing` is element-mutable), 6.6 (`SafetyTextColor` doc implied conditional behavior, method ignored its parameter). "The doc says X, the code permits not-X."

**E. The `Color32` struct-equality / boxing trap (carried 6.1 lesson) shaped every story's test style** — forcing per-channel / `Hex.Packed` compares throughout, which intersected the internal-visibility trap in 6.6.

**F. The "fake exit 0 / stale lockfile" headless trap recurred (6.5)** — first run exited 0 with no `test-results.xml` + 3 CS0117; a stale `Temp/UnityLockfile` needed clearing. Caught because the `unity-headless-testing` discipline ("never trust exit 0") was followed.

## 4. CR effectiveness — the 3 AC violations it caught

All three are one meta-class — **a test that passes for the wrong reason** (the `tautological-test-trap`):

1. **6.4 — premise-count desync.** Presenter built `PremiseBeats.Count` cards; flow walked `const 3`. The AC allows 2–3 cards, so a 2-card content pass advances past an index the presenter never built → **crash / blank card on the first screen a new player sees.** Green because both sources agreed at 3. *Fix:* derive `PremiseCardCount => PremiseBeats.Count`.
2. **6.6 — no-op reduced-motion adapter.** First shipped only the port + a no-op; "persists + reads back true" would pass against a non-persisting adapter → **the a11y setting silently resets every launch** (UX-DR17 failure certified working). *Fix:* ship the concrete `SaveModelReducedMotionSetting` + 4 real round-trip pins.
3. **6.6 — vacuous safety firewall.** `SafetyTextColor` ignored its parameter → "muted-never-for-safety" was convention, not structure. *Fix:* read `treatment.IsSafetyException`.

**Other classes the CR reliably caught:** ordering/race/TOCTOU (6.3 — all 8 confirmed findings converged on one fire-and-forget race the dev's *own spec line* warned against; the sync-commit fix dissolved 3 hazard windows at once); self-defeating test guards (6.1).
