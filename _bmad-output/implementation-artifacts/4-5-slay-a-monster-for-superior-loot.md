# Story 4.5: Slay a Monster for superior loot

Status: done

## Story

As a player,
I want to slay a Monster for better rewards,
So that the hunter playstyle pays off over collecting.

## Acceptance Criteria

**AC-1 (Slay costs 3 Credits, shown before spend, deducted in ONE atomic write; a SUCCESS records the `Slain` Codex discovery — X/67 +1 if newly discovered).**
**Given** a settled Monster in a live encounter AND a balance ≥ 3 Credits
**When** the player taps Slay and the attempt SUCCEEDS
**Then** the cost (3 Credits, `EconomyConfig.SlayCost`) is knowable before the spend (carried on the result / readable via the system), EXACTLY 3 Credits are deducted, AND the Monster's Codex entry is added/updated via Epic 2's discovery (`DiscoverySource.Slay` → the `Slain` flag set, `OnMonsterDiscovered` raised + `DiscoveredCount` incremented IFF it is the first discovery) — the deduction AND the discovery commit in ONE `SaveAsync` (AR-8), whole-mutation rollback on fault.

**AC-3 (a FAILED Slay leaves the encounter active and offers a FREE Retry; no Credits are lost and no Codex discovery is recorded on failure).**
**Given** a settled Monster
**When** a Slay attempt FAILS (the success roll misses)

## Dev Notes

### The five atomic-write siblings (4.5 adds the fifth)
EncounterService hosts a family of composed writers, all sharing the AR-8 pipeline (acquire `SaveMutationLock` once → capture `_saveService.Current` once → mutate in memory → ONE `SaveAsync` → recovery-swap guard → whole-mutation rollback on fault → events after release):
1. `CommitActionAsync` (4.1) — charge consume + codex discovery (the generic primitive; `RunActionAsync` drives it). **NOT used by Slay** (it consumes a CHARGE + grants NO XP; Slay spends CREDITS + grants XP — a different delta).
2. `CommitLureSpendAsync` (4.2) — credit spend, no codex, no XP.
3. `CommitScanAsync` (4.3) — FREE, scan-flag/encounter-state, no economy.
4. `CommitCaptureAsync` (4.4) — a ROLL-aware write: charge (Strong) + codex + XP, roll-gated.
5. **`CommitSlayAsync` (4.5, NEW)** — a ROLL-gated write: CREDITS (3) + codex (`Slain`) + XP (`XpPerSlay`), committed ONLY on a winning roll (a miss deducts nothing — AC-3 / architecture.md:648 "no free-Slay via two persists" + "no Credits lost on a failed Slay").

**Why Slay is a NEW sibling, not a reuse of `CommitActionAsync` (settles the 4.4 deferral):** the 4.4 dev deferral left Slay to decide whether to fold `StageXpGrant` into `RunActionAsync`/`CommitActionAsync`. The answer is NO: `CommitActionAsync` consumes a CHARGE and grants NO XP. Slay's delta is `credits + codex + Slain + XpPerSlay` — it matches no existing sibling, so it gets its own composed write. It reuses the credit-spend SLICE shape from `CommitLureSpendAsync` and the discovery+XP SLICE shape from `CommitCaptureAsync`'s winning branch.

**The roll-gating wrinkle (the AC-3 heart):** unlike Lure (an unconditional spend) and like Capture (a roll-gated discovery), Slay's spend is itself roll-gated — the 3 Credits are deducted ONLY on a winning roll. A MISS mutates nothing (save-count 0). This is the only reading consistent with BOTH AC-3 "no Credits lost on a failed Slay" AND "Retry is free" — see Decision C.
