# Story 3.5: Save and restore anchors across interruption

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a player,
I want a placed object to come back if AR hiccups or I leave and return,
So that I never lose my encounter to a lost anchor.

## Acceptance Criteria

**AC-1 (a saved anchor is a serializable `AnchorToken` storable in `EncounterSnapshot`/`SaveModel`).**
**Given** `IArAnchorProvider`
**When** an anchor is saved
**Then** it produces a serializable `AnchorToken` (trackable id + session-relative pose) storable in `EncounterSnapshot`/`SaveModel`.
[Source: docs/epics.md#Story-3.5 (AC-1); docs/architecture.md:409 (IArAnchorProvider — SaveAnchor→AnchorToken; TryRestoreAnchor), :452-454 (AnchorToken in Core/Contracts, below AR, so snapshots store it without an upward edge); FR-4. NOTE: the persistence STORAGE already exists — `EncounterSnapshotData.Anchors : AnchorToken[]` on `SaveModel`, with `SaveJson` serialization + `SaveRoundTripTests` coverage. 3.5 VERIFIES the round-trip + adds the `IsValid` coercion; it does NOT add new `SaveModel` fields.]

**AC-2 (`Restored` → the object re-anchors in place).**
**Given** a restore attempt `TryRestoreAnchor(token, out AnchorRestoreResult)`
**When** the result is `Restored`
**Then** the object re-anchors in place.
[Source: docs/epics.md#Story-3.5 (AC-2); docs/architecture.md:469-470 (Restored → re-anchor in place); AnchorRestoreResult.Restored (Core/Contracts, already defined Story 1.2).]

**AC-3 (`RelocatedToPlane` → nearest plane in the camera frustum, fallback to absolute-nearest, never vanish).**
**Given** the result is `RelocatedToPlane`
**When** the anchor was lost
**Then** the object re-places on the nearest plane within the current camera frustum (fallback to absolute-nearest only if nothing is in view) with a brief "pulled back through the veil" beat (reusing Lure VFX) — it never vanishes.
[Source: docs/epics.md#Story-3.5 (AC-3); docs/architecture.md:471-473 (RelocatedToPlane → nearest plane within current camera frustum, fall back to absolute-nearest only if nothing is in view, diegetic "pulled back through the veil" beat reusing Lure materialization VFX, never vanish). The frustum-nearest-plane SELECTION is the testable decision 3.5 owns; the "pulled back through the veil" Lure-VFX beat is Epic 4/6 (no Lure VFX exists yet) — DEFER.]

**AC-4 (`Failed` / mid-session interruption → `OnArSessionInterrupted`, guidance, never crash; encounter can suspend pending recovery).**
**Given** the result is `Failed`, or the session is interrupted mid-session
**When** AR loss occurs
**Then** `OnArSessionInterrupted` is raised, the encounter shows guidance (never a crash, NFR-3), and the encounter can enter a suspended/paused state pending recovery.
[Source: docs/epics.md#Story-3.5 (AC-4); docs/architecture.md:650-652 (mid-session AR loss → ArSessionService raises OnArSessionInterrupted; the EncounterStateMachine Suspended state pauses + shows guidance; on recovery attempt TryRestoreAnchor), :38/:217 (NFR-3 degrade to guidance). NOTE: `OnArSessionInterrupted` is ALREADY raised by `ArSessionService` (Story 3.3). The `EncounterStateMachine.Suspended` CONSUMER is Epic 4 — 3.5 owns the restore DECISION returning a typed `Failed`/guidance result; the encounter-side Suspended state is DEFERRED.]

### The design decisions this story locks (call them out for the CR reviewer)
1. **The seam is absorbed, not duplicated (decision #1 + the 3.4 decision #6 mandate).** `IArPlaneAnchorProvider` becomes the architecture-named `IArAnchorProvider` (architecture.md:409) owning BOTH save (3.4 forward members, kept verbatim) AND restore (new `TryReacquireAnchor` + `TryGetRelocationCandidates`). The seam stays THIN (architecture.md:466) — it exposes re-acquire + candidate-plane primitives; the `Restored`/`RelocatedToPlane`/`Failed` + nearest-in-frustum DECISION lives in the pure-logic `AnchorRestoreService`. The `.meta` GUID is PRESERVED on rename (rename the file, keep the GUID) so no references break.
2. **`AnchorToken.IsValid`/`None` settle the 1.2 deferral (decision: read-guard, not ctor-throw).** `IsValid => !string.IsNullOrEmpty(trackableId)`; `None => default`. The type stays a serializable DTO that accepts any value on LOAD (the Persistence coercion precedent); `IsValid` is the READ-time "is this a real anchor?" guard the restore path uses to treat a None/corrupt token as "no anchor → relocate or fail", never crashing (NFR-3).
3. **The nearest-in-frustum-else-absolute-nearest relocation is THE testable decision (AC-3).** `RelocatedToPlane` picks the nearest candidate with `InCameraFrustum == true`; only if NONE are in frustum does it fall back to the absolute-nearest (architecture.md:471-473 "nearest plane within the current camera frustum (fall back to absolute-nearest only if nothing is in view)"). Pinned by a test where an in-frustum-but-farther plane beats an out-of-frustum-nearer plane (mutation-testable). The object NEVER vanishes — `Failed` is a typed guidance state, not a disappearance.

### Edge cases & boundary rules (must-handle — these become test cases)
- **`Restored` (AC-2):** valid token + re-acquire succeeds → `Restored`, `ReacquireCalls == 1`, no relocation query.
- **`RelocatedToPlane` nearest-in-frustum (AC-3):** re-acquire fails; an in-frustum-farther plane beats an out-of-frustum-nearer plane → relocate to the in-frustum one. THE pin.
- **`RelocatedToPlane` absolute-nearest fallback (AC-3):** re-acquire fails; NO plane in frustum → relocate to the absolute-nearest. Pins the fallback clause.
- **`Failed` (AC-4):** re-acquire fails AND no candidates → `Failed` + warn, no throw, object never vanishes.
- **Invalid/None token (Task 2 / AC-4):** `!token.IsValid` → no re-acquire attempt (`ReacquireCalls == 0`); relocate if a candidate exists, else `Failed`. No throw on a junk/None token.
- **Re-acquire preferred over relocate (AC-2 vs AC-3):** both available → `Restored` wins, `GetRelocationCandidatesCalls == 0`.
- **`AnchorToken.IsValid`/`None`:** `default`/`None`/null-or-empty-trackableId → `IsValid == false`; a real token → `true`.
- **AC-1 round-trip (verify):** `EncounterSnapshotData.Anchors` still round-trips through `SaveJson` (existing test stays green); optionally an invalid token round-trips and is `!IsValid` after load.
