# Story 4.1: Drive the encounter with an explicit state machine

Status: done

## Story

As a developer,
I want an explicit encounter state machine,
So that actions are well-ordered and the encounter can be suspended and resumed faithfully.

## Acceptance Criteria

**AC-1 (the `EncounterStateMachine` moves through the defined states + a `Suspended` state on AR loss; `EncounterService` exposes the FR-6–10 actions via constructor/Init injection, NOT the service locator).**
**Given** `EncounterStateMachine`
**When** an encounter runs
**Then** it moves through Idle → Lured → Acting → Resolving → Resolved, with a `Suspended` state on AR loss
**And** `EncounterService` exposes the FR-6–10 actions and receives dependencies via constructor/Init injection (not the service locator).
[Source: docs/epics.md#Story-4.1 (AC-1, lines 604-607); docs/architecture.md:413-414 (EncounterService FR-6–10 constructor/Init injection; EncounterStateMachine Idle→Lured→Acting→Resolving→Resolved), :456-459 (service-locator rule — Encounter is pure-logic, ctor/Init-injected, must NOT call GameServices.Get<T>()), :516 (encounter flow driven by EncounterStateMachine), :66 (AR-9 explicit EncounterStateMachine + Suspended on AR loss), :650-652 (Suspended state on AR loss).]

**AC-2 (one transactional save write per player action: balance/charge delta AND encounter/codex delta commit together; a persist failure rolls back the WHOLE in-memory mutation — never deduct-and-resolve in two separate persists).**
**Given** any single player action (Lure/Slay/Capture/extra)
**When** it resolves
**Then** the balance/charge delta AND the encounter/codex delta are committed in ONE atomic save write
**And** a persist failure rolls back the whole in-memory mutation (never deduct-and-resolve in two separate persists).
[Source: docs/epics.md#Story-4.1 (AC-2, lines 609-612); docs/architecture.md:644-649 (AR-8 — one transactional write per player action; a spend + its action-resolution must commit together; on persist failure roll the WHOLE in-memory mutation back; never deduct credits and resolve the action in two separate persists — prevents free-Slay / resurrected-monster inconsistencies), :328 (credit/charge spends are atomic: validate→deduct→perform→persist), :765 (one atomic save write per player action; never split a spend and its resolution).]

**AC-3 (AR interruption mid-encounter → `Suspended` + guidance; on recovery, attempt anchor restore per Epic 3.5).**
**Given** AR interruption mid-encounter
**When** `OnArSessionInterrupted` fires
**Then** the machine enters `Suspended` and shows guidance; on recovery it attempts anchor restore per Epic 3.5.
[Source: docs/epics.md#Story-4.1 (AC-3, lines 614-616); docs/architecture.md:650-652 (mid-session AR loss → ArSessionService raises OnArSessionInterrupted; the EncounterStateMachine gains a Suspended state that pauses the encounter + shows guidance, never a crash NFR-3; on recovery, attempt TryRestoreAnchor per the rehydrate rules), :87 (Mid-session AR loss: OnArSessionInterrupted → EncounterStateMachine Suspended + guidance; on recovery attempt TryRestoreAnchor), :468-476 (TryRestoreAnchor → Restored/RelocatedToPlane/Failed + state-faithful restoration). NOTE: the `AnchorRestoreService.TryRestore` DECISION + `OnArSessionInterrupted` event ALREADY exist (Stories 3.3/3.5). 4.1 builds the CONSUMER: the Suspended state + the recovery CALL SITE that invokes TryRestore.]

### Edge cases & boundary rules (must-handle — these become test cases)
- **Illegal state transition:** warned no-op (`GameLog.Warn`, state unchanged, returns false), never throws (e.g. `Idle → Acting` skipping `Lured`).
- **Atomic commit (AC-2):** a composed action does EXACTLY ONE `SaveAsync` (assert count == 1); both economy + codex slices reflect the new values on success.
- **Whole-mutation rollback (AC-2):** a persist fault reverts BOTH slices to pre-action values + returns a typed failure (never a faulted task). Mutation-testable: reverting one slice but leaking the other → red.
- **Recovery-swap guard (AC-2):** `_saveService.Current` swapped mid-persist → rollback + `PersistenceFailed` (the ProgressionService/CodexService swap-branch contract).
- **Suspend on interruption (AC-3):** active encounter + `OnArSessionInterrupted` → `Suspended` + guidance. Idle encounter + interruption → safe no-op (don't suspend Idle).
- **Recovery → TryRestore (AC-3):** `Restored`/`RelocatedToPlane` → leave `Suspended`; `Failed` → stay `Suspended` + guidance, never vanish. Assert `TryRestore` was called (seam call count).
- **Insufficient credits (AR-11):** a composed action that can't afford its spend raises `OnInsufficientCredits` (does NOT open Shop/Billing); the world does not lock; nothing is persisted on the rejected spend.
- **Ctor null args:** every `EncounterService`/`EncounterStateMachine` ctor arg null → `ArgumentNullException`. No `GameServices.Get` anywhere in Encounter.

**Patched (real findings):**
- [x] [Review][Patch] **`Recover()` auto-resumed a suspended encounter with ZERO anchors without restoring anything (major / AC-3 violation).** When `_activeAnchors` is empty, the `foreach` never ran, so `TryRestore` was never called and the method fell through to `Resume()` + returned `Restored` — a false "Restored" claiming a restore that never happened (`BeginLure` permits an empty array; 4.2's spawn fills it later). Fix: guard the empty case explicitly — log + stay `Suspended` + return `Failed` (nothing to re-acquire, NFR-3 never a false success). Pinned by `Recovery_of_a_zero_anchor_encounter_stays_suspended_without_a_false_restore` (asserts `Suspended` + `ReacquireCalls == 0` + `GetRelocationCandidatesCalls == 0`). [Assets/Veilwalkers/Encounter/EncounterService.cs (Recover)]
- [x] [Review][Patch] **Deferred-suspend (decision H2) hardcoded the resume target to `Lured`, ignoring the actual resolve target (minor).** `EncounterStateMachine.ResolveTo` set `_stateBeforeSuspend = EncounterState.Lured` when applying a deferred suspend — so a suspend deferred during an `EndEncounter` (target `Resolved`) would resume to `Lured`, not the intended terminal. Fix: `_stateBeforeSuspend = target` (derive from the resolve, don't bake in Lured). Pinned by `Deferred_suspend_during_EndEncounter_resumes_to_Resolved_not_Lured`. [Assets/Veilwalkers/Encounter/EncounterStateMachine.cs (ResolveTo)]
